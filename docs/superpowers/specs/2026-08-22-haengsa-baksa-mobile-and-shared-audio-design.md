# 행사박사 — 모바일 반응형과 공용 음원 설계서

2026-08-22

휴대폰에서 글씨·줄간격·테두리가 겹치는 문제를 화면마다가 아니라 뿌리에서 고치고,
처음 앱을 여는 다른 선생님이 백지 상태에서 겪는 문턱을 낮춘다.

## 배경

실기기 확인에서 두 가지가 드러났다.

- **새 행사 만들기** — 날짜 입력칸이 장소 입력칸 위로 올라타 테두리가 겹친다.
- **식순 편집** — 순서 제목이 2~3줄로 접혀 카드 높이가 제각각이다.

그리고 이 앱은 계정도 서버도 없이 모든 것을 기기 안 IndexedDB에 담는다.
바깥으로 나가는 통신은 `gemini/client.ts`의 Gemini 호출 하나뿐이다.
그래서 다른 사람이 배포 주소를 열면 **학교명·음원·행사·API 키가 전부 빈 백지 앱**을 만난다.
"나만 쓸 수 있는" 것이 아니라 "누구나 쓸 수 있지만 각자 백지에서 시작해야 하는" 상태다.

넘어야 할 문턱은 셋이다.

1. Gemini API 키를 직접 발급받아 넣기 — 압도적으로 크다
2. 음원 4개를 직접 구해 등록 — 교가만 학교마다 다르고 나머지는 전국 공통이다
3. 학교명·교장 성함 입력 — 이건 각자 몫이라 없앨 수 없다

## 세 덩어리

| | 내용 | 선행 조건 |
|---|---|---|
| A | 모바일 반응형 정리 (전 화면) | 없음 |
| B | 공용 음원 라이브러리와 버전 선택 | mp3 파일을 저장소에 올림 |
| D | 동영상 재생 (직접 올리기) | 없음 |
| C | 첫 실행 온보딩과 API 키 없는 길 | B · D |

A → B → D → C 순으로 간다. A와 D는 완전히 독립이고, C는 앞의 것들을 안내해야 하므로 맨 뒤다.

## A. 모바일 반응형

### A-1. 글씨 크기를 뿌리에서 반응시킨다

Tailwind v4는 `@theme`의 `--text-*`를 `text-base` 같은 유틸리티로 만든다.
`src/index.css`에서 이 값을 `clamp()`로 바꾸면 **화면 코드를 한 글자도 고치지 않고**
전 화면의 글씨가 화면 폭에 비례해 움직인다.

```css
--text-base: clamp(0.95rem, 0.9rem + 0.30vw, 1.10rem);
```

작은 폰(320px)에서 0.95rem, 큰 화면에서 1.10rem까지 늘고 그 밖으로는 안 나간다.
줄간격은 `--text-*--line-height`로 같이 묶는다. 한글은 영문보다 넉넉해야 읽히므로
본문 계열은 1.65, 제목 계열은 1.35를 준다.

기존 화면이 쓰는 `text-xs · text-sm · text-base · text-lg · text-xl · text-2xl · text-3xl · text-5xl`
전부를 정의한다. 하나라도 빠뜨리면 그 크기만 Tailwind 기본값으로 남아 결이 어긋난다.

### A-2. 겹침은 원인을 없앤다

날짜칸이 장소칸을 밀고 들어오는 진짜 원인은 flex 아이템의 기본값 `min-width: auto`다.
아이폰의 `input[type="date"]`는 "2026. 8. 21."을 표시할 고유 폭을 끝까지 고집하고,
`min-width: auto`는 그 고집을 그대로 통과시킨다. `flex-1`은 이길 수 없다.

두 겹으로 막는다.

1. `index.css`에 전역 안전장치 — 모든 `input · select · textarea`에 `min-width: 0`과 `max-width: 100%`
2. 날짜·장소 쌍은 `flex`를 `grid grid-cols-1 sm:grid-cols-2`로 — 좁은 폰에서는 아예 위아래로 쌓는다

1번은 앞으로 만들 화면에서도 같은 사고를 막는다.
해당 위치는 `NewEventPage.tsx`와 `OutlineReviewPage.tsx` 두 곳이다(같은 결함이 복사되어 있다).

### A-3. 한 줄에 일곱 개를 넣지 않는다

`SegmentCard`는 지금 한 줄에 `[배지][제목][시간][▲][▼][삭제][펼치기]`가 있다.
오른쪽 여섯이 폭을 먼저 가져가 제목만 짓눌린다.

제목 줄과 조작 줄을 나눈다. 제목은 전체 폭을 쓰므로 대부분 한 줄에 들어간다.
조작 줄은 `flex-wrap`이라 더 좁아져도 겹치지 않고 아래로 흐른다.
`EditorPage` 헤더와 `PageHeader`도 같은 처방을 받는다.

### A-4. 손가락으로 누를 수 있게

`▲ ▼ 삭제 펼치기`가 `px-2`뿐이라 세로 터치 영역이 글자 높이만 하다.
최소 44×44px을 준다(애플 권장치). 공통 부품에 `IconButton`을 두어 반복을 없앤다.

### A-5. 아이폰 하단 여백

`viewport-fit=cover`는 이미 index.html에 있다. `body`에 `env(safe-area-inset-*)`를 반영해
홈 인디케이터 바에 버튼이 가리지 않게 한다.

## B. 공용 음원 라이브러리

### B-1. 어디에 두나

**같은 저장소의 `public/audio/`**. 배포하면 `ahnbagsa.github.io/event/audio/…`가 된다.

- 같은 오리진이라 브라우저 보안(CORS) 설정이 아예 필요 없다
- `vite.config.ts`의 프리캐시 목록이 `{js,css,html,png,svg,woff2}`라 **mp3는 프리캐시되지 않는다** —
  음원을 늘려도 앱 설치가 무거워지지 않는다
- 배포는 `main` push로 이미 자동이다

### B-2. 목록은 파일 하나가 정의한다

`public/audio/library.json`.

```json
{
  "version": 1,
  "tracks": [
    {
      "id": "anthem-band-1",
      "role": "anthem",
      "label": "애국가 1절 (관악 반주)",
      "file": "anthem-band-1.mp3",
      "note": "전주 4마디 포함",
      "credit": "교육부 배포본",
      "durationSec": 69
    }
  ]
}
```

같은 `role`에 여러 줄을 넣으면 **앱이 알아서 선택 목록을 만든다.**
애국가 세 가지, 묵념곡 두 가지 — 파일을 올리는 만큼 늘어난다. 앱 코드는 안 고친다.

`durationSec`은 목록에 표시하기 위한 것이고, 실제 저장할 때는 파일에서 다시 읽는다
(`readAudioDuration`이 이미 있다). 손으로 적은 값이 틀려도 재생에는 영향이 없다.

교가(`schoolSong`)는 라이브러리에 두지 않는다. 학교마다 다르므로 기존 파일 업로드를 유지한다.

### B-3. 고르면 내려받아 기기에 저장한다

스트리밍하지 않는다. **행사 당일 강당에서 와이파이가 끊겨도 재생돼야 하기 때문이다.**

고르는 순간 `fetch` → `arrayBuffer` → 기존 `putAudio`로 IndexedDB에 넣는다.
`AudioAsset.data`가 이미 `ArrayBuffer`라 업로드로 넣은 음원과 완전히 같은 취급을 받는다.
`putAudio`가 같은 역할의 기존 음원을 지우는 동작도 그대로 맞다 — 애국가를 다시 고르면 교체된다.

미리듣기는 다르다. 들어보기만 할 때는 내려받지 않고 주소를 그대로 재생한다.
고르지 않을 파일까지 기기에 쌓을 이유가 없다.

### B-4. 없어도 망가지지 않는다

`library.json`이 없거나, 비어 있거나, 인터넷이 끊겨 있으면
**라이브러리 칸을 조용히 접고 기존 파일 업로드만 보여준다.** 오류를 띄우지 않는다.
음원 파일은 사용자가 준비하는 것이므로, 파일이 아직 없는 동안에도 앱은 지금과 똑같이 동작해야 한다.

### B-5. 저작권

저장소에 올린 파일은 누구나 받을 수 있게 공개된다.
맹세문·애국가·묵념곡은 공공 성격이라 대체로 괜찮지만 특정 음반 녹음은 안 된다.
`credit` 필드에 출처를 적고 음원 서랍에 함께 보여준다.

## D. 동영상

강당 빔프로젝터에 애국가 영상을 띄우는 것은 학교에서 흔한 쓰임이다.

### D-1. 구조는 이미 받쳐 준다

`AudioController`는 구체적인 `<audio>`가 아니라 `MediaLike` 인터페이스에만 의존한다.

```ts
export type MediaLike = { play(): Promise<void>; pause(): void; currentTime: number; volume: number };
```

`<video>` 요소가 이 넷을 그대로 만족하므로 **재생·일시정지·처음부터·페이드아웃은 한 줄도 고치지 않는다.**
저장 구조(`AudioAsset.data`가 `ArrayBuffer`)도 종류를 가리지 않는다.

고칠 곳은 넷이다.

| 위치 | 지금 | 고칠 것 |
|---|---|---|
| `usePlayer.ts` | `new Audio(url)` 고정 | mimeType이 `video/`면 `<video>`를 만든다 |
| `readAudioDuration.ts` | `new Audio()`로 길이 측정 | 영상은 `<video>`로 잰다 |
| `mimeFromName.ts` | `audio/`만 인정 | `video/`와 mp4·webm·mov 확장자 |
| `RunPage` | 영상이 나올 자리가 없다 | 아래 D-3 |

### D-2. 직접 올리기만 받는다

공용 라이브러리(GitHub)는 **음원만** 담는다. 영상은 각 학교가 자기 기기에 직접 올린다.

애국가 영상 1분이 10~30MB인 반면 mp3는 1~2MB다. 저장소에 영상을 넣으면
GitHub의 파일당 100MB 한도에 부딪히고 `git clone`이 무거워진다.
직접 올리기는 저장소 부담이 0이고, 교가 영상처럼 학교마다 다른 것에도 맞는다.

`AudioAsset`은 이름만 음원이지 실제로는 미디어 서랍이다. 타입에 `kind: 'audio' | 'video'`를
더해 화면이 종류를 알 수 있게 한다. 기존에 저장된 자료는 `kind`가 없으므로
**읽을 때 `mimeType`으로 판정한다** — 마이그레이션 없이 예전 데이터가 그대로 열려야 한다.

### D-3. 진행 화면 — 작게 보이다가 크게 보기

평소에는 대본이 주인공이다. 영상은 재생 줄에 작게(가로 160px 정도) 뜬다.
**크게 보기**를 누르면 브라우저 전체화면 API로 영상만 화면을 채운다.

이렇게 하면 한 벌로 두 가지 쓰임을 다 덮는다.

- 사회자가 폰으로 대본 보며 진행 — 평소 상태 그대로
- 빔프로젝터에 연결된 기기 — 크게 보기를 눌러 영상만 송출

전체화면 API는 iOS Safari에서 `<video>` 요소에만 통하고 일반 요소에는 막혀 있다.
영상 요소 자체를 전체화면으로 보내므로 이 제약에 걸리지 않는다.
그래도 실패할 수 있으니(권한 거부 등) 실패하면 조용히 원래대로 둔다.

## C. 온보딩과 API 키 없는 길

### C-1. 첫 실행 안내

학교 프로필이 없으면 홈에서 안내를 띄우고 세 걸음으로 이끈다.

1. 학교명·교장 성함
2. 공용 음원 고르기 (B가 있어야 의미가 있다)
3. AI 연결 — **건너뛸 수 있다**

세 걸음 모두 건너뛸 수 있어야 한다. 강제로 붙잡으면 안내가 아니라 관문이 된다.

### C-2. 키가 없어도 막히지 않게

지금은 API 키가 없으면 어디서 막히는지 알기 어렵다.
식순 짜기와 행사 진행은 키 없이도 전부 되므로, AI 버튼 자리에만
"키를 넣으면 멘트를 자동으로 써 드립니다 — 없어도 직접 쓰실 수 있습니다"를 보인다.

## 검증

- 공통 부품과 새 모듈에 테스트를 붙인다. 기존 344개는 계속 통과해야 한다
- 레이아웃은 자동 테스트로 눈 확인을 대신할 수 없다.
  320 · 375 · 430px 폭에서 사람이 직접 본다 — 이건 실기기 확인 항목으로 남는다

## 하지 않는 것

- 계정·로그인·클라우드 동기화 — 별도 설계가 필요한 훨씬 큰 작업이다
- AI 비용을 대신 부담하는 서버 프록시 — 운영비와 남용 방지가 평생 따라붙는다
- 다크 모드 — `AppSettings.theme`이 자리만 있고 쓰이지 않는다. 이번 범위 밖이다
