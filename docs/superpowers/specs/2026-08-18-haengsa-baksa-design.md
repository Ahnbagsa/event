# 행사박사 (行事博士) — 설계 문서

- 작성일: 2026-08-18
- 상태: 승인됨 (구현 계획 작성 대기)
- 대상 사용자: 초등학교 교무부장 1인 (추후 타 학교 교사 공유 가능성)

---

## 1. 목적

초등학교 의식행사(개학식·방학식·입학식·졸업식·기념식·시상식)의 **대본 작성부터 당일 진행까지**를 한 앱에서 처리한다.

기존 업무 흐름의 문제:

- 사회 대본을 매번 한글 파일로 새로 작성한다.
- 대본(종이)과 음향(방송실 PC)이 분리되어 있어 큐 신호 실수가 발생한다.
- 강당 PC가 준비되지 않으면 진행 자체가 어려워진다.

이 앱이 해결하는 것:

1. 계획서를 넣으면 **대상·진행방식에 맞는 사회자 멘트**를 자동 생성한다.
2. 행사 당일 **대본과 음원을 한 화면에서** 진행한다.
3. PC가 없으면 **휴대폰만으로도 행사를 진행**할 수 있다.

## 2. 핵심 사용 시나리오

### S1. 행사 준비 (PC, 행사 1주 전)

교무부장이 개학식 계획서를 PDF로 내보내 업로드한다. 앱이 식순을 추출해 카드로 보여주고, 교사가 확인·수정한다. 대상(전교생)·진행방식(교실 방송)·톤을 고르면 순서별 사회자 멘트가 생성된다. 편집기에서 문장을 다듬고 각 순서에 음원(애국가·묵념곡·교가)을 연결한다.

### S2. 행사 진행 (PC, 강당/방송실)

행사 5분 전 "행사 전 점검"을 통과한다(음원 누락·소리 확인·화면 꺼짐 방지). 진행 모드로 들어가 큰 글씨 대본을 보며 `다음` 버튼으로 넘긴다. 애국가 순서에서 재생 버튼을 누르면 음원이 나가고, 묵념은 타이머가 함께 돈다.

### S3. 비상 진행 (휴대폰)

강당 PC가 켜지지 않는다. 교사가 폰에서 앱을 열고(홈 화면에 설치되어 있음), 이미 등록해둔 음원과 링크로 받은 시나리오로 그대로 진행한다. 폰을 강당 스피커에 연결한다.

### S4. 이동 중 확인 (휴대폰)

회의 중 대본을 확인하고 문구를 수정한다.

## 3. 범위

### 이번 범위에 포함

- 학교 프로필 관리
- 음원 서랍 (역할 기반 등록·저장·재생)
- 계획서 입력 4종: 텍스트 붙여넣기 / PDF 업로드 / 사진 업로드 / 폼 직접 입력
- 표준 식순 템플릿 (개학식 우선, 이후 확장)
- 시나리오 편집기 (순서 편집, 멘트 편집, 음원 연결, 부분 재생성)
- Gemini 연결 계층 (모델 자동 탐색 · 폴백 · 한국어 오류 변환 · 연결 테스트)
- AI 시나리오 생성 (식순 추출 + 멘트 생성)
- 행사 전 점검
- 진행 모드 (PC 가로 / 폰 세로 모두 지원)
- 폰 전송 링크 (URL 압축 공유)
- PWA (오프라인 실행, 홈 화면 설치)
- GitHub Pages 배포

### 이번 범위에서 제외 (후속)

- 인쇄용 대본 PDF, 전체 백업/복원 파일
- 개학식 외 나머지 템플릿 (입학식·졸업식·기념식·시상식) — 구조만 잡고 순차 추가
- 두 기기 실시간 연동 (PC 음향 + 폰 대본)
- 클라우드 계정·자동 동기화
- 다중 학교 관리, 사용자 계정

## 4. 아키텍처

### 4.1 전체 형태

**서버가 없는 정적 웹앱.** 모든 데이터는 브라우저 안에 저장되고, 외부 통신은 Gemini API 호출뿐이다.

```
┌─────────────────── 브라우저 (PC / 폰) ───────────────────┐
│                                                          │
│  React UI                                                │
│    ├─ 설정 (프로필 · 음원서랍 · API키 · 연결테스트)      │
│    ├─ 행사 마법사 (입력 → 식순확인 → 정보 → 생성)        │
│    ├─ 시나리오 편집기                                    │
│    ├─ 행사 전 점검                                       │
│    └─ 진행 모드                                          │
│                                                          │
│  도메인 로직 (순수 함수 — 테스트 대상)                   │
│    ├─ modelPicker    모델 점수화·선택                    │
│    ├─ errorMapper    Gemini 오류 → 한국어                │
│    ├─ scenarioLink   압축 인코딩/디코딩                  │
│    ├─ timeEstimator  예상 시간 계산                      │
│    ├─ preflight      빈칸·음원누락 검사                  │
│    └─ runMachine     진행 모드 상태 전이                 │
│                                                          │
│  저장소 (IndexedDB)                                      │
│    profile · audio(Blob) · events · settings · runState  │
│                                                          │
└──────────────────────────┬───────────────────────────────┘
                           │ HTTPS (시나리오 생성 시에만)
                           ▼
              Google Generative Language API
```

### 4.2 설계 원칙

1. **진행 모드는 네트워크를 쓰지 않는다.** 행사 당일 와이파이에 의존하지 않는다.
2. **AI가 죽어도 앱은 산다.** 내장 템플릿 + 수동 편집만으로 완전한 대본을 만들 수 있다.
3. **모델 이름을 코드에 박지 않는다.** 실행 시점에 API에 물어본다.
4. **AI는 사실을 지어내지 않는다.** 모르는 값은 빈칸으로 남긴다.
5. **음원은 파일이 아니라 역할로 참조한다.** 기기가 달라도 시나리오가 그대로 동작한다.

## 5. 데이터 모델

TypeScript 타입으로 정의한다. 모두 IndexedDB에 저장한다.

```ts
type SchoolProfile = {
  id: 'singleton';
  schoolName: string;                              // "○○초등학교"
  principal: { title: string; name: string };      // 직함, 성함
  vicePrincipal?: { title: string; name: string };
  foundedDate?: string;                            // 개교기념일 (YYYY-MM-DD)
  updatedAt: number;
};

type AudioRole =
  | 'pledge'      // 국기에 대한 맹세
  | 'anthem'      // 애국가
  | 'silence'     // 묵념곡
  | 'schoolSong'  // 교가
  | 'entrance'    // 입장곡
  | 'exit'        // 퇴장곡
  | 'award'       // 시상 배경음
  | `custom:${string}`;

type AudioAsset = {
  id: string;
  role: AudioRole;
  label: string;          // 화면 표시명 "애국가 (1절)"
  blob: Blob;             // 실제 파일
  mimeType: string;
  durationSec: number;    // 등록 시 실측
  fileName: string;
  addedAt: number;
};

type SegmentKind =
  | 'speech'    // 사회자 멘트만
  | 'audio'     // 음원 재생 동반
  | 'timer'     // 묵념 등 시간 고정
  | 'address';  // 학교장 말씀 등 외부 발화 (시간만 확보)

type Segment = {
  id: string;
  order: number;
  name: string;                     // "애국가 제창"
  groupLabel: string | null;        // "국민의례" — 화면에서 묶어 표시할 때만 사용
  kind: SegmentKind;
  script: string;                   // 사회자 멘트 (빈칸 {{...}} 포함 가능)
  audioRole: AudioRole | null;
  autoPlay: boolean;                // 기본 false
  fadeOutSec: number | null;        // 페이드아웃 길이
  timerSec: number | null;          // timer 종류일 때
  manualDurationSec: number | null; // address 종류일 때 (기본 180)
  note: string;                     // 음향·조명 지시 등 진행자 메모
};
```

**순서 목록은 평면 배열이다.** 국민의례처럼 하위 절차가 있는 경우도 중첩 구조를 만들지 않고, 각 순서에 같은 `groupLabel`을 부여해 화면에서만 묶어 보여준다. 진행 모드는 그룹을 무시하고 한 순서씩 넘어간다.

`kind`와 `audioRole`은 독립이다. 묵념은 `kind: 'timer'`이면서 `audioRole: 'silence'`를 가진다 — 타이머가 도는 동안 묵념곡이 재생된다.

### IndexedDB 스토어

| 스토어 | 키 | 비고 |
|---|---|---|
| `profile` | `'singleton'` | 학교 프로필 |
| `audio` | `id` | `role` 인덱스 |
| `events` | `id` | `updatedAt` 인덱스 |
| `settings` | `'singleton'` | API 키 포함 |
| `runState` | `'singleton'` | 진행 중단 복구용 |

내장 템플릿은 저장하지 않고 코드에 상수로 둔다(앱 업데이트 시 함께 갱신되어야 하므로).

## 6. 화면 상세

### 6.1 홈 — 행사 목록

- 저장된 행사 카드 (제목, 날짜, 순서 수, 예상 시간)
- 카드 액션: `편집` `진행` `링크 복사` `삭제`
- `＋ 새 행사 만들기`
- 학교 프로필 또는 API 키가 없으면 상단에 설정 안내 배너

### 6.2 설정

**학교 프로필** — 학교명, 교장/교감 직함·성함, 개교기념일.

**음원 서랍** — 역할별 슬롯. 각 슬롯에 파일 드롭 또는 선택. 등록 시 `HTMLAudioElement`로 재생 길이를 실측해 저장. 슬롯마다 미리듣기 버튼. 사용자 정의 역할 추가 가능.

**Gemini API 키** — 입력 후 저장 시 자동으로 모델 탐색 수행. 발급 방법 안내 포함.

**연결 테스트** — 7.6절 참조.

### 6.3 새 행사 만들기 (4단계)

**1단계 · 계획서 넣기**

네 가지 입력 경로를 한 화면에 둔다.

- 큰 텍스트 영역 (붙여넣기)
- 파일 드롭존 (PDF / PNG / JPG) — 여러 개 가능
- `폼으로 직접 입력` 전환
- `템플릿에서 시작` (AI 없이 바로 3단계로)

파일과 텍스트는 함께 보낼 수 있다.

**2단계 · 식순 확인**

AI가 추출한 순서를 카드 목록으로 보여준다. 여기서 확정해야 멘트를 만든다.

- 드래그로 순서 변경, 카드 삭제
- `＋ 순서 추가` (표준 순서 목록에서 고르거나 빈 카드)
- 각 카드의 종류(멘트/음원/타이머/말씀) 지정
- 표준 템플릿과 다른 점을 배너로 안내: "표준 개학식에는 있는 '교가 제창'이 없습니다. 추가할까요?"

**3단계 · 행사 정보**

제목 · 날짜 · 장소 · **진행방식(대면/방송)** · 대상 · 톤 · 목표 시간.

`대면 ↔ 방송`은 멘트를 크게 바꾸므로 눈에 띄게 배치한다.

**4단계 · 생성**

진행 표시와 함께 멘트 생성. 완료 시 편집기로 이동.

### 6.4 시나리오 편집기

상단 고정 바: 행사 제목 · **총 예상 시간** · 빈칸 개수 경고 · `저장` `점검하러 가기` `링크 복사`

순서 카드 목록 (드래그 정렬). 카드 펼침 시:

| 항목 | 편집 방식 |
|---|---|
| 순서명 | 텍스트 |
| 멘트 | 여러 줄 텍스트. `{{빈칸}}`은 노란 배경으로 강조 |
| 음원 | 역할 선택 드롭다운 (서랍에 없는 역할은 ⚠ 표시) |
| 자동 재생 | 토글 (기본 끔) |
| 페이드아웃 | 없음 / 3초 / 5초 |
| 타이머 | 30초 / 1분 / 직접 입력 (`timer` 종류) |
| 말씀 시간 | 분 단위 입력 (`address` 종류) |
| 진행 메모 | 텍스트 — 진행 모드에 회색으로 표시 |
| 🔄 이 순서만 다시 생성 | AI 재생성 (앞뒤 순서를 맥락으로 전달) |

### 6.5 행사 전 점검

진행 모드로 들어가는 **유일한 경로.** 항목을 모두 통과해야 `진행 시작` 버튼이 활성화된다.

| 항목 | 통과 조건 | 실패 시 |
|---|---|---|
| 빈칸 없음 | `{{...}}` 0개 | 남은 위치 목록 표시, 클릭 시 편집기로 이동 |
| 음원 준비 | 시나리오가 요구하는 모든 역할이 이 기기 서랍에 존재 | 누락 역할 표시 + 그 자리에서 등록 |
| 소리 확인 | 테스트음 재생 후 사용자가 `들렸어요` 클릭 | 안내: 아이폰 무음 스위치 / 볼륨 / 스피커 연결 |
| 화면 유지 | Wake Lock 요청 성공 | 미지원 시 경고만 (차단하지 않음) |
| 방해금지 | 사용자 확인 체크박스 | — |

하단에 **총 예상 소요 시간**과 순서별 시간 표를 함께 보여준다.

소리 확인 단계에서 오디오를 실제로 한 번 재생함으로써 **iOS의 자동재생 잠금이 함께 해제된다** — 점검 절차와 기술적 요구가 자연스럽게 일치한다.

### 6.6 진행 모드

레이아웃(세로/가로 공통, 반응형):

```
상단   행사명 · 3/8 · 경과 04:12 · 🔒잠금 · A+ A- · 목록
본문   현재 멘트 (대형) + 진행 메모(회색, 작게)
음원   [역할명] ▶재생 ⏸ ↺처음부터 ⤵페이드 · 진행바 · 볼륨
       (timer 종류일 때는 카운트다운을 크게 표시)
미리   다음 ▸ 순국선열에 대한 묵념
하단   ◀ 이전            다음 ▶
```

- 키보드: `→` 다음, `←` 이전, `Space` 재생/정지, `F` 전체화면
- `목록`으로 임의 순서 점프
- 🔒 잠금: 켜면 다음/이전이 **길게 눌러야** 동작 (폰 오작동 방지)
- 기본 테마는 어두운 배경 + 밝은 글씨
- 현재 위치를 `runState`에 저장 → 새로고침·창 닫힘 후 재개 제안
- 마지막 순서 다음은 종료 화면 (총 소요 시간 표시)

## 7. Gemini 연결 계층

이 프로젝트에서 **가장 실패하기 쉬운 지점**이므로 독립 모듈로 분리한다.

### 7.1 문제

- 모델 이름이 자주 바뀌고, 구 모델은 예고 없이 404가 된다.
- API 키마다 사용 가능한 모델 목록이 다르다.
- `v1`과 `v1beta`의 지원 범위가 다르다.
- 원문 오류가 영문 JSON이라 사용자가 원인을 알 수 없다.

### 7.2 해결 — 실행 시점 탐색

```
GET {base}/{apiVersion}/models?key={apiKey}
```

응답의 각 모델에서 `name`, `displayName`, `supportedGenerationMethods`, `inputTokenLimit`, `outputTokenLimit`를 읽는다.

**절차**

1. `v1beta`로 목록 요청 → 실패하면 `v1`로 재시도. 성공한 버전을 `settings.apiVersion`에 저장한다.
2. `supportedGenerationMethods`에 `generateContent`가 없는 모델을 제외한다.
3. `modelPicker`로 점수를 매겨 정렬하고 최상위를 `selectedModel`로 저장한다.
4. 결과 전체를 `discoveredModels`에 캐시한다(오프라인 대비).

> 구현 시 실제 응답 필드명을 0단계 스파이크에서 확인한 뒤 확정한다. 위 필드명은 공개 문서 기준이며, 차이가 있으면 스파이크 결과를 따른다.

### 7.3 modelPicker 점수 규칙 (순수 함수)

모델명 문자열에서 판단한다. 특정 이름을 하드코딩하지 않는다.

| 조건 | 가중치 |
|---|---|
| 이름에서 파싱한 버전 숫자 (`2.5` → 2.5) | `+ version * 100` |
| `flash` 포함 | `+ 50` |
| `pro` 포함 | `+ 10` |
| `lite` 포함 | `- 15` |
| `preview` / `exp` / `experimental` 포함 | `- 80` |
| `thinking` 포함 | `- 20` (출력 토큰 소모가 큼) |
| `embedding` / `aqa` / `imagen` / `veo` / `tts` 포함 | 후보에서 제외 |

동점이면 `outputTokenLimit`가 큰 쪽을 택한다.

사용자는 설정에서 드롭다운으로 직접 고를 수 있다. 수동 선택(`modelPinnedByUser: true`)은 자동 선택보다 우선하며, 해당 모델이 목록에서 사라진 경우에만 자동 선택으로 되돌아간다.

### 7.4 요청 실패 시 폴백

```
generate(request)
  → selectedModel 로 호출
  → 404 / NOT_FOUND / 모델 관련 400
        ↳ 모델 목록 재탐색 → 다음 후보로 1회 재시도
        ↳ 성공 시 조용히 진행하고 "모델이 ○○로 변경되었습니다" 안내 표시
  → 429  응답의 retryDelay 파싱 → 카운트다운 후 자동 1회 재시도
  → 503 / 500  지수 백오프 재시도 (최대 3회: 1s, 2s, 4s)
  → 그 외  errorMapper로 한국어 변환 후 사용자에게 표시
```

### 7.5 errorMapper (순수 함수)

| 조건 | 한국어 메시지 |
|---|---|
| `API_KEY_INVALID` / 400 + key 관련 | API 키가 올바르지 않습니다. 키를 다시 복사해 붙여넣어 주세요. |
| 403 / `PERMISSION_DENIED` | 이 키로는 Gemini API 사용이 허용되지 않았습니다. Google AI Studio에서 키를 다시 발급해 주세요. |
| 404 / `NOT_FOUND` (폴백 실패 후) | 사용 가능한 모델을 찾지 못했습니다. 설정 → 연결 테스트를 눌러 확인해 주세요. |
| 429 / `RESOURCE_EXHAUSTED` | 무료 사용량을 초과했습니다. 약 N초 후 자동으로 다시 시도합니다. |
| 503 / 500 / `UNAVAILABLE` | 서버가 혼잡합니다. 자동으로 다시 시도 중입니다 (n/3). |
| `SAFETY` / `blockReason` | 내용 일부가 안전 필터에 걸렸습니다. 문구를 조금 바꿔 다시 생성해 보세요. |
| 네트워크 오류 | 인터넷 연결을 확인해 주세요. 이미 만들어둔 시나리오는 그대로 사용할 수 있습니다. |

### 7.6 연결 테스트 화면

버튼 하나로 다음을 순차 실행하고 각 줄에 성공/실패를 표시한다.

1. API 키 형식 확인
2. 모델 목록 조회 → 발견 개수
3. 현재 선택된 모델 표시
4. 짧은 텍스트 생성 테스트 (`"안녕하세요"` 응답 확인) + 소요 시간
5. PDF 첨부 지원 확인 (작은 더미 PDF 1장 전송)

부가 조작: `모델 직접 고르기` 드롭다운, `목록 새로고침`.

## 8. AI 시나리오 생성

### 8.1 호출 1 — 식순 추출

**입력**: 사용자 원문(텍스트) + 첨부(PDF/이미지 inline data) + 학교 프로필

**출력 스키마**

```json
{
  "detectedEventType": "semester-opening",
  "title": "2026학년도 2학기 개학식",
  "date": "2026-08-18",
  "place": "각 교실",
  "segments": [
    { "name": "개식사", "kind": "speech", "note": "" },
    { "name": "국기에 대한 경례", "kind": "audio", "note": "맹세문 낭독" }
  ]
}
```

`responseMimeType: "application/json"` + `responseSchema`를 사용한다. 모델이 스키마를 지원하지 않으면 "JSON만 출력하라"는 프롬프트로 전환하고, 응답에서 코드펜스를 제거한 뒤 첫 `{`부터 마지막 `}`까지를 추출하는 **관대한 파서**로 폴백한다.

식순을 찾지 못하면 `detectedEventType`만 채우고 `segments`를 비워 반환한다 → 앱이 해당 템플릿을 제안한다.

### 8.2 호출 2 — 멘트 생성

**입력**: 확정된 식순 + 행사 정보(진행방식·대상·톤·목표 시간) + 학교 프로필

**출력 스키마**

```json
{
  "segments": [
    { "id": "seg-1", "script": "지금부터 ...", "estimatedSeconds": 12 }
  ]
}
```

`id`는 앱이 부여한 값을 그대로 돌려받아 매칭한다(순서 뒤바뀜 방지). 응답에 없는 `id`는 빈 멘트로 두고 사용자에게 표시한다.

`estimatedSeconds`는 **참고용으로만 받고 저장하지 않는다.** 실제 표시 시간은 항상 `timeEstimator`가 글자 수와 음원 실측 길이로 계산한다 — AI의 추정을 신뢰하지 않는다.

**부분 재생성**: 대상 순서 1개 + 앞뒤 각 1개를 맥락으로 전달하고, 대상 순서의 `script`만 받는다.

### 8.3 프롬프트 가드레일

시스템 지시에 다음을 명시한다.

1. **사실을 지어내지 말 것.** 학교명·성함·날짜·인원·수상자 등은 제공된 값만 사용한다. 제공되지 않은 값은 `{{교장 성함}}`처럼 이중 중괄호 빈칸으로 남긴다.
2. **진행방식을 반영할 것.**
   - `inPerson`: "자리에서 일어서 주시기 바랍니다"
   - `broadcast`: "각 교실에서 모두 일어서 주세요. 화면을 향해 서 주시기 바랍니다"
3. **대상에 맞춘 어휘.**
   - `lower`: 짧은 문장, 쉬운 낱말
   - `upper`: 표준 정중체
   - `all`: 고학년 기준이되 저학년이 이해할 어휘
   - `withParents`: 격식 상향, 내빈 인사 포함
4. **사회자가 실제로 읽을 문장만 쓸 것.** 지시문·괄호 설명·무대 지시는 넣지 않는다.
5. **목표 시간이 주어지면** 전체 멘트 분량을 그에 맞춘다.
6. 국민의례·묵념 등 의식 절차의 **표준 표현을 임의로 바꾸지 않는다.**

### 8.4 빈칸 검증

생성 결과에서 이중 중괄호 패턴으로 빈칸을 수집한다.

- 편집기: 노란 배경 강조 + 상단에 개수 표시
- 행사 전 점검: 1개라도 있으면 **차단**

## 9. 오디오 설계

### 9.1 저장과 재생

- 등록 시 `Blob`으로 IndexedDB에 저장. 재생 시 `URL.createObjectURL`로 `HTMLAudioElement`에 연결하고 언마운트 시 해제한다.
- 등록 시 `loadedmetadata`에서 `duration`을 실측해 저장한다.
- 페이드아웃은 `volume`을 `requestAnimationFrame`으로 감쇠시킨 뒤 정지한다.

### 9.2 모바일 제약과 대응

| 제약 | 대응 |
|---|---|
| iOS는 사용자 제스처 없이 재생 불가 | 행사 전 점검의 "소리 확인" 단계에서 실제 재생 → 잠금 해제 |
| iOS 무음 스위치가 켜져 있으면 무음 | 점검 단계에서 사용자가 귀로 확인하고 `들렸어요`를 눌러야 통과 |
| 진행 중 화면 꺼짐 | Screen Wake Lock API. `visibilitychange` 시 재획득. 미지원 시 경고만 |
| 전화 수신 시 오디오 중단 | 점검 단계에서 방해금지 모드 안내 |
| **iOS Safari가 미사용 사이트의 저장 데이터를 삭제** | **홈 화면 추가(PWA 설치) 시 예외.** 폰 최초 진입 시 설치 안내를 필수 단계로 표시 |
| 저장 용량 | `navigator.storage.estimate()`로 잔여량 표시. `persist()` 요청 |

## 10. 진행 모드 상태 기계

```
IDLE ──(점검 통과)──▶ READY ──(진행 시작)──▶ RUNNING ──(마지막 다음)──▶ FINISHED
                                              │  ▲
                                     next/prev/jump
                                              └──┘
```

각 순서의 오디오 상태:

```
NONE → LOADED → PLAYING ⇄ PAUSED → FADING → STOPPED
```

전이 규칙:

- 순서 이동 시 이전 오디오는 즉시 정지하고 새 오디오를 `LOADED`까지만 준비한다.
- `autoPlay`가 켜진 순서만 `PLAYING`으로 자동 전이한다.
- `timer` 종류는 재생과 동시에 카운트다운을 시작하고, 0에 도달하면 화면 강조와 함께 `다음` 버튼을 시각적으로 부각한다(자동 이동은 하지 않는다).

`runMachine`은 UI와 분리된 순수 함수로 구현해 테스트한다.

## 11. 공유와 배포

### 11.1 폰 전송 링크

`EventCeremony`에서 오디오 Blob을 제외한 JSON → `lz-string`의 `compressToEncodedURIComponent` → URL 해시에 담는다.

```
https://{user}.github.io/{repo}/#/import?d={compressed}
```

개학식 시나리오 기준 원본 약 4~6KB, 압축 후 1.5~3KB로 예상한다. 브라우저 URL 한계를 크게 밑돈다.

**한계 처리**: 압축 결과가 8KB를 넘으면 링크 대신 파일 내보내기를 안내한다.

수신 측은 링크를 열면 미리보기 후 `가져오기`로 저장한다. 음원은 포함되지 않으므로, 수신 기기의 서랍에서 역할로 해석된다.

### 11.2 GitHub Pages 배포

프로젝트 페이지 형태(`{user}.github.io/{repo}/`)를 전제로 한다.

- `vite.config.ts`에 `base: '/{repo}/'` 설정
- 라우팅은 **해시 라우터**를 사용한다(Pages는 SPA 폴백을 지원하지 않으므로). 공유 링크가 이미 해시 기반이라 자연스럽다.
- `vite-plugin-pwa`의 `scope`와 `start_url`을 `base`에 맞춘다.
- `.nojekyll` 파일을 추가한다(밑줄로 시작하는 자산 경로 보호).
- GitHub Actions로 `main` 푸시 시 빌드 후 Pages 배포.

**주의**: 저장소를 공개(public)로 두면 코드가 공개된다. API 키는 코드가 아니라 사용자 브라우저에 저장되므로 저장소에는 포함되지 않는다. 키를 소스에 하드코딩하지 않는다.

## 13. 개발 순서

```
0  프로젝트 셋업 · IndexedDB 계층 · 학교 프로필
   + [스파이크] 모델 자동 탐색이 실제 키로 동작하는지 확인
1  음원 서랍 (등록 · 저장 · 미리듣기 · 길이 실측)
2  개학식 템플릿 + 시나리오 편집기        ← AI 없이 대본 완성 가능
3  행사 전 점검 + 진행 모드
   ══════ 2학기 개학식 실전 투입 가능 지점 ══════
4  GitHub Pages 배포 · PWA · 폰 전송 링크  ← 폰 사용 가능
5  Gemini 연결 계층 (탐색 · 폴백 · 오류 변환 · 연결 테스트)
6  AI 시나리오 생성 (식순 추출 · 멘트 생성 · 부분 재생성)
```

AI를 뒤에 두는 이유: 개학식이 임박한 상황에서 AI부터 만들면 당일 사용 가능한 결과물이 없다. 3단계까지 먼저 완성하면 최악의 경우에도 수동으로 대본을 넣어 행사를 진행할 수 있다. 다만 가장 불확실한 모델 탐색은 0단계에서 스파이크로 미리 검증한다.

```
2-1  국기에 대한 경례          audio    role=pledge      ※ 약식 옵션
2-2  애국가 제창               audio    role=anthem      ※ 절 수 선택
2-3  순국선열에 대한 묵념      timer    role=silence     ※ 30초 / 1분
3    학교장 말씀               address  기본 180초
4    교가 제창                 audio    role=schoolSong
5    폐식사                    speech
```

약식 국민의례(국기에 대한 경례만 수행)를 옵션으로 제공한다.

### 기본 식순에 넣지 않는 표준 순서

학교와 행사에 따라 넣기도 하고 빼기도 하는 순서들이다. 기본 식순에서 제외하고, 편집기의 `＋ 순서 추가`에서 한 번에 넣을 수 있게 한다.

```
전달 사항           address  기본 120초   ※ 교무·생활·보건
내빈 소개           speech
축사                address  기본 180초
시상                audio    role=award
학생 대표 인사      address  기본 120초
입장                audio    role=entrance
퇴장                audio    role=exit    ※ 페이드아웃 3초
```

`전달 사항`을 기본에서 뺀 근거: 사용자(교무부장) 확인 결과 학교장 말씀은 항상 있으나 전달 사항은 그때그때 다르다.

## 15. 위험 요소

| 위험 | 영향 | 대응 |
|---|---|---|
| Gemini 응답 형식이 예상과 다름 | 식순 추출 실패 | 0단계 스파이크로 조기 확인, 관대한 파서, 템플릿 폴백 |
| iOS에서 저장 음원 소실 | 폰 진행 불가 | PWA 설치 필수 안내, 점검 단계에서 음원 존재 확인 |
| 무료 API 한도 초과 | 생성 불가 | 429 자동 대기·재시도, 수동 편집 경로 항상 유지 |
| 브라우저 데이터 삭제로 자료 소실 | 전체 손실 | 백업 파일 내보내기는 이번 범위 밖 — 사용자에게 명시적으로 안내하고 후속에서 추가 |
| GitHub Pages 경로 문제 | 배포본 백지 | `base` 설정 + 해시 라우터 + `.nojekyll` |
