# 행사박사 다듬기 설계서 (디자인·모바일·공유)

**작성일:** 2026-08-21
**전제:** 계획서 1·2·3의 구현이 모두 끝나 `main`에 병합되어 있고 `https://ahnbagsa.github.io/event/`에 배포되어 있다.

## 1. 목표

지금 앱은 동작은 하지만 투박하다. 화면마다 색과 간격이 제각각이고, 만든 사람의 흔적이 없다.
여기에 실제로 써 보니 드러난 결함 두 가지가 있다 — 휴대폰에서 음원을 고를 수 없고, 공유 링크가 너무 길다.

이 설계서는 네 가지를 다룬다.

1. 화면 전체에 공통으로 쓸 색·간격·모양 규칙을 들이고 모든 화면에 적용한다
2. 안박사 캐릭터를 앱 얼굴로 쓰고, 첫 화면에 만든 사람을 밝힌다
3. 휴대폰에서 음원 파일이 선택되지 않는 문제를 고친다
4. 공유 링크를 짧게 만들고, QR로도 옮길 수 있게 한다

**바꾸지 않는 것:** 도메인 로직, 데이터 구조(IndexedDB 스키마), 화면 이동 경로, AI 호출 계층.
이 작업은 겉모습과 두 개의 결함에 한정한다.

## 2. 디자인 원칙

안박사는 검정 선으로 그린 동그란 캐릭터다. 앱도 같은 결이어야 한다.

- **종이와 먹.** 밝은 종이색 바탕에 먹색 글씨. 캐릭터의 선과 같은 검정을 본문·테두리에 쓴다.
- **모서리는 둥글게.** 카드는 16px, 주요 버튼은 완전한 알약 모양.
- **색은 아껴 쓴다.** 강조색은 하나만. 나머지는 종이·먹·회색으로 해결한다.
- **선은 얇게, 그림자는 거의 없이.** 테두리 1px, 그림자는 떠 있어야 하는 것에만.
- **글자는 크게.** 교무실에서 나이 지긋한 선생님도 읽는다. 본문 16px를 기본으로 한다.

### 색

`src/index.css`에 Tailwind v4의 `@theme`로 정의한다. 값은 CSS 변수로 나가므로 진행 모드에서 덮어쓸 수 있다.

| 이름 | 값 | 쓰임 |
|---|---|---|
| `paper` | `#FDFBF6` | 화면 바탕 |
| `paper-raised` | `#FFFFFF` | 카드 바탕 |
| `ink` | `#1B1917` | 본문 글씨, 진한 테두리 |
| `ink-soft` | `#6B635C` | 보조 설명 글씨 |
| `line` | `#E7E0D5` | 카드·입력칸 테두리 |
| `accent` | `#C75B2A` | 주요 버튼, 선택된 상태 (따뜻한 주황) |
| `accent-soft` | `#FCEDE4` | 강조 배경, 안내 상자 |
| `ok` | `#2F6B4F` | 성공 |
| `warn` | `#B45309` | 주의 |
| `danger` | `#B02A24` | 삭제·오류 |
| `stage` | `#14110F` | 진행 모드 바탕 (따뜻한 검정) |

지금 쓰이는 `bg-blue-600`·`bg-slate-900`·`bg-amber-100`·`text-gray-600` 등은 전부 위 이름으로 바꾼다.
진행 모드는 이미 어두운 배경(`slate-900`)을 쓰고 있는데, 차가운 회색 대신 `stage`로 바꿔 나머지 화면과 같은 계열로 만든다.

### 크기와 간격

- 화면 최대 너비: 지금처럼 `max-w-xl`(설정·마법사) / `max-w-2xl`(홈·편집기) 유지
- 카드 안쪽 여백 16px, 카드 사이 간격 12px
- 버튼 높이: 주요 48px, 보조 40px (휴대폰에서 손가락으로 누를 수 있는 크기)

## 3. 공통 부품

`src/ui/kit/`에 넣는다. 지금은 화면마다 같은 버튼을 다른 클래스로 각자 쓰고 있어, 색 하나 바꾸려면 17개 파일을 고쳐야 한다.

| 부품 | 하는 일 |
|---|---|
| `Button.tsx` | `variant`: `primary`(강조색 채움) · `secondary`(테두리) · `ghost`(글씨만) · `danger`. `size`: `md` · `lg`. `disabled`일 때 회색 처리까지 한곳에서 맡는다 |
| `Card.tsx` | 흰 바탕 · 1px 테두리 · 둥근 모서리 상자 |
| `PageHeader.tsx` | 뒤로가기 링크 + 제목 + 오른쪽 슬롯. 지금 8개 화면이 제각각 만들고 있다 |
| `Notice.tsx` | 안내 상자. `tone`: `info` · `warn` · `danger` |
| `AnbaksaMark.tsx` | 안박사 캐릭터 SVG (아래 4절) |

부품은 그 이상 만들지 않는다. 입력칸·선택칸은 공통 클래스 문자열 하나(`fieldClass`)로 충분하다.

## 4. 안박사 마크와 크레딧

`ahnbagsa.svg`는 캐릭터(y 40~400)와 "안박사" 글자(y 420~525)가 한 파일에 들어 있다.
글자 부분을 `<g data-part="wordmark">`로 묶고, viewBox를 바꿔 두 가지로 쓴다.

- `variant="mark"` — `viewBox="40 20 330 400"`, 글자 숨김. 얼굴만 나온다
- `variant="full"` — `viewBox="0 0 400 550"`, 글자 포함

원본의 `stroke="#050505"`·`fill="#050505"`는 `currentColor`로 바꾼다. 그래야 진행 모드의 어두운 배경에서도 흰 선으로 나온다.
흰자위로 쓰인 `fill="#ffffff"`는 카드 바탕색을 따라야 하므로 `fill="var(--color-paper-raised)"`로 바꾼다.

파일은 `src/ui/kit/AnbaksaMark.tsx`에 **인라인 React 컴포넌트로** 넣는다. `<img>`로 불러오면 색을 바꿀 수 없고 요청이 한 번 더 나간다.
저장소 뿌리의 `ahnbagsa.svg`·`ahnbagsa.png`는 원본으로 그대로 둔다.

## 6. 휴대폰 음원 선택 고치기

### 진단

두 곳이 막고 있다.

**(1) `AudioDrawer.tsx`의 `accept="audio/*"`**
안드로이드 파일 관리자와 카카오톡이 내려받은 mp3는 종류를 `application/octet-stream`으로 보고하는 일이 잦다.
브라우저는 `audio/*`와 맞지 않는다고 보고 파일을 회색으로 막는다.
아이폰은 `audio/*`를 보면 파일 앱보다 음악 보관함을 먼저 여는데, 거기 곡은 보호가 걸려 있어 읽을 수 없다.

**(2) `readAudioDuration.ts`가 파일이 보고한 종류를 그대로 믿는다**
`new Blob([data], { type: mimeType })`에서 `mimeType`이 빈 문자열이면 `<audio>`가 형식을 몰라 `onerror`로 떨어진다.
(1)을 고쳐 파일을 고를 수 있게 되어도 여기서 "음원 파일을 읽을 수 없습니다"가 뜬다.

### 해법

`src/audio/mimeFromName.ts`를 새로 만든다.

```ts
guessAudioMime(fileName: string, reportedType: string): string
```

- `reportedType`이 `audio/`로 시작하면 그대로 쓴다
- 아니면 확장자로 정한다: `.mp3`→`audio/mpeg`, `.m4a`·`.mp4`→`audio/mp4`, `.aac`→`audio/aac`,
  `.wav`→`audio/wav`, `.ogg`·`.oga`→`audio/ogg`, `.flac`→`audio/flac`, `.opus`→`audio/ogg`
- 확장자도 모르면 `audio/mpeg`로 본다 (대부분 mp3다. 틀렸으면 재생 시도에서 걸러진다)

`AudioDrawer`는 `accept`를 넓힌다.

```
accept="audio/*,.mp3,.m4a,.aac,.wav,.ogg,.oga,.flac,.opus"
```

확장자를 함께 적으면 종류를 잘못 보고하는 파일도 선택할 수 있다.

`handleFile`은 `file.type` 대신 `guessAudioMime(file.name, file.type)`의 결과를 쓴다. 저장하는 `mimeType`도 이 값이다.

오류 문구도 고친다. 지금은 "mp3 파일인지 확인해 주세요"라 원인이 짐작되지 않는다.

> 음원 파일을 읽을 수 없습니다. mp3·m4a·wav 파일인지 확인해 주세요.
> 휴대폰이라면 카카오톡이나 다운로드 폴더에 받아 둔 파일을 골라 주세요.

### 손으로 확인할 것

자동 테스트로는 파일 선택창 자체를 확인할 수 없다. 배포 후 실제 휴대폰에서 봐야 한다.

## 7. 공유 링크 짧게

### 지금

멘트까지 채운 개학식 한 건이 **1,865자**다. 카카오톡 대화창을 가득 채운다.
원인은 압축률이 아니라 **버려도 되는 것을 담고 있어서**다 — 순서마다 붙은 내부 id(`seg-...`), 순번, 만든 시각·고친 시각.
전부 가져올 때 새로 만드는 값이라 링크에 담을 이유가 없다.

### v2 형식

객체 대신 배열로, 자리로 뜻을 정한다.

```
[2, title, templateId, date, place, modeIdx, audienceIdx, toneIdx, targetMinutes, segments]
segment = [name, kindIdx, script]            // 기본값뿐이면 3칸
        | [name, kindIdx, script, extra]     // 기본값이 아닌 것만 extra에
extra = { r?: 역할, a?: 1, t?: 초, m?: 초, f?: 초, g?: 묶음이름, n?: 메모 }
```

- `modeIdx`·`audienceIdx`·`toneIdx`·`kindIdx`는 고정 목록의 자리 번호
- `r`(음원 역할)은 표준 역할이면 자리 번호, `custom:...`이면 문자열 그대로
- `a`(자동재생)는 참일 때만, `t`·`m`·`f`는 null이 아닐 때만, `g`·`n`은 비어 있지 않을 때만 넣는다

결과: **1,865자 → 853자** (54% 감소).

이보다 더 줄이려면 서버가 필요한데(단축 URL), 서버 없이 도는 것이 이 앱의 장점이므로 하지 않는다.
압축 알고리즘을 바꿔도(deflate 743자) 얻는 것에 비해 브라우저 지원 조건이 붙어 권하지 않는다.

### 옛 링크도 열려야 한다

이미 배포되어 있어 v1 링크가 밖에 나가 있을 수 있다. `decodeScenario`는 둘 다 읽는다.

- 압축을 푼 결과가 **배열**이고 첫 칸이 `2`면 v2
- **객체**이고 `id`·`title`·`segments`를 가지면 v1 (지금 로직 그대로)
- 둘 다 아니면 기존 오류

`encodeScenario`는 v2로만 만든다.

### QR 코드

PC에서 만든 시나리오를 휴대폰으로 옮기는 것이 링크의 본래 목적이다. 853자라도 카카오톡에 붙이면 여전히 길다.
QR을 함께 보여주면 길이가 아예 상관없어진다 — 휴대폰 카메라로 찍으면 끝이다.

`ShareButton`을 눌렀을 때 **복사 + QR 그림**을 함께 내놓는다.

- `qrcode-generator` 사용 (의존성 없음. 설치 시 크기를 확인하고, 30KB를 넘으면 넣지 않고 링크 복사만 남긴다)
- QR은 `<canvas>`가 아니라 SVG로 그린다. 인쇄와 확대에 강하다
- 853자는 QR 버전 20 언저리로 들어간다. 화면에 240px로 띄우면 휴대폰이 읽는다
- 링크가 QR 한도(약 2,300자)를 넘으면 QR 없이 "링크가 길어 QR로 만들 수 없습니다. 복사해서 보내 주세요."를 띄운다

## 8. PWA 아이콘과 테마색

지금 아이콘은 파란 바탕에 "행" 글씨다. 새 색과 맞지 않고, 안박사가 있는데 굳이 글씨를 쓸 이유가 없다.

- `public/icon-192.png`·`icon-512.png`를 **종이색 바탕 + 먹색 안박사 얼굴**로 다시 만든다
- `vite.config.ts`의 `theme_color`를 `#C75B2A`, `background_color`를 `#FDFBF6`으로 바꾼다
- `index.html`의 `<meta name="theme-color">`도 같이 바꾼다

아이콘은 계획서 2에서 쓴 방식(윈도우 System.Drawing)으로는 SVG를 그릴 수 없다.
`resvg`·`sharp` 같은 것을 새로 들이지 않고, **브라우저에서 SVG를 canvas에 그려 PNG로 내려받는 임시 페이지**를 만들어 두 장을 뽑은 뒤 그 페이지는 지운다.

## 9. 테스트

- **공통 부품**: `Button`·`Notice`의 variant별 렌더링, `AnbaksaMark`의 variant별 viewBox와 wordmark 표시 여부
- **`guessAudioMime`**: 확장자별 매핑, 보고된 종류 우선, 모르는 확장자의 기본값 — 순수 함수라 테스트하기 쉽다
- **`AudioDrawer`**: 종류가 빈 파일을 넣어도 저장되는지 (지금은 실패한다)
- **`scenarioLink`**: v2 왕복, v1 링크 읽기(하위호환), 길이가 실제로 줄었는지, 8KB 한도
- **`ShareButton`**: QR이 그려지는지, 너무 길 때 안내가 나오는지
- **기존 299개**: 전부 통과해야 한다. 클래스만 바뀌므로 원칙적으로 깨지지 않아야 하고, 깨진다면 그 테스트가 겉모습에 기대고 있었다는 뜻이므로 함께 고친다

## 10. 하지 않는 것

- 다크 모드 전환 스위치 — `AppSettings.theme`이 자리만 잡고 쓰이지 않는다. 진행 모드가 이미 어둡고, 나머지 화면까지 두 벌로 관리할 이유가 지금은 없다
- 글꼴 도입 — 시스템 글꼴로 충분하다. 웹폰트는 오프라인 실행과 용량에 부담이다
- 애니메이션 — 행사 당일 손이 급한 화면에 움직임은 방해가 된다
- 단축 URL 서버
- 화면 구조·이동 경로 변경
